Sanctum

From application to sanction in minutes, with a credit officer still in charge

A point-of-view for Retail Lending: an agentic AI layer for salaried personal loans (₹1–15 lakh, 12–60 months), built on a single lakehouse that brings together policy documents, core banking data and external checks.

Act 1 — One place for everything the decision needs

Today the credit officer opens a bureau portal, the core banking screen, a stack of PDFs and a policy folder. The data is correct but scattered. The lakehouse fixes that first.

Documents

RBI circulars, credit policy, KYC, salary slips, statements. Read once, stored as searchable text and fields.

Bank data

Customers, accounts, existing loans, repayments from core banking, refreshed continuously.

External checks

Bureau, PAN, Aadhaar e-KYC, Account Aggregator, employer. Fetched with consent, every response logged.

Act 2 — Agents that do the legwork, humans who decide

Intake agent
Reads documents, flags mismatches
→
Credit agent
Pulls data, checks policy, computes FOIR, writes reasons
→
Credit officer
Approves, modifies, refers or rejects
→
Sanction & disburse
KFS, e-sign, e-mandate, payout

Arithmetic and hard rules run as plain code, so they never drift. The AI reads, reasons and explains. Every reason cites the data point and the policy clause it relied on.

Architecture

Functional layers on the left, the Google Cloud services that implement them on the right.

Channels
Applicant portal and officer workbench (web app, Cloud Run). API gateway and role-based sign-in.
Agent runtime
Orchestrator (FastAPI on Cloud Run) managing session state and handoffs. Intake agent and Credit agent as bounded specialists; Claude or Gemini as reasoning model; deterministic code for EMI, FOIR and cut-offs.
Tool box
BigQuery query tool, policy vector search (RAG), bureau, PAN/Aadhaar, Account Aggregator and employer checks via mock services, exposed as functions or MCP tools.
Lakehouse
BigQuery bronze, silver and gold datasets. Cloud Storage for documents with object tables, Document AI for extraction, embeddings and vector index for policies.
Ingestion
Datastream or batch loads from core banking, Cloud Storage uploads for documents, API response logging for external data.
Human in the loop
Officer decision screen, delegated-authority routing, override reasons stored as feedback for policy and prompt tuning.
Governance
IAM, row and column security, PII masking, consent records, Dataplex lineage, Cloud Audit Logs, versioned prompts and policies, bias and drift review aligned to RBI’s FREE-AI principles.
Not applicable
CERSAI is excluded because a personal loan has no collateral. It returns when the same platform extends to home loans.

About & FAQ

Sanctum is a presales point-of-view demo for banking customers. It uses synthetic data only and is not a production system.

Will AI approve loans on its own?

No. The agents recommend with reasons. A credit officer makes the final decision.

How are hallucinations prevented?

Policy answers are retrieved with citations, calculations are deterministic code, and low-confidence or flagged cases go to a human.

How do policy changes reach the agents?

New circulars and policy versions are uploaded, indexed and used at the next case, with no code change.

How is customer data protected?

Consent capture, masking, role-based access and full audit logs, in line with DPDP and RBI expectations.

Why BigQuery?

Serverless SQL, vector search, object tables for documents and built-in governance in one platform.
